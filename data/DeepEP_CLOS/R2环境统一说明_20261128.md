## 2. `run_round2.py` 具体改动

- `NODES` 扩为 8 台；`REPO` / `STAGE` / `CONTAINER_HINT` / `RUNTIME` 按上表统一；新增 `GOLDEN_DIR`、`PROXY`、`PRECISION_BENCH_FILES`。
- `env_prefix()`：PYTHONPATH 改为 `STAGE : BENCH_DIR : GOLDEN_DIR : ($PYTHONPATH)`，去掉不存在的 `/workspace/runtime`。
- `git_in()`：注入代理，保证 gate 里的 `fetch --quiet origin main` 在 8 机容器内可执行。
- 新增 `deploy_bench_files()`；`stage_precision` / `stage_abnormal` 启动前把精度 bench 补丁部署到参与节点。
- `precision_argv()`：精度 bench 改用 `STAGE + "/bench_v*_precision.py"` **绝对路径**。
- 文案：门禁从「四机」改「八机」；拓扑段改写；`require_gate()` 提示同步。
- **用例与波次语义完全不变**：`EP_NODES = {8:[3], 16:[2], 32:[0,1], 64:[0,1,2,3]}` 保持，R2 最多 EP64=4 机，仍只用 node0..node3；node4..node7 参与 gate 八机一致性校验但不跑测。

## 3. 新增文件

| 文件 | 说明 |
|---|---|
| `scripts/bench_v1_precision.py` | 精度 bench 本地补丁（20 KB） |
| `scripts/bench_v2_precision.py` | 精度 bench 本地补丁（55 KB） |

**原因**：`lueelu/DeepEP` main 仓的 `benchmarks/clos/` 里**没有** `bench_v1_precision.py` / `bench_v2_precision.py`
（只有 bandwidth 系列、`bench_fast_sweep.py`、`profiling.py`、`route_workloads.py`、`stage_metrics.py`）。
这两个是从原先 64P 环境复制的本地补丁，R2 的 C 精度阶段与 D 异常阶段（worker import `bench_v2_precision`）都依赖它们。

**为什么部署到 `/work/round2` 而不是塞进 `REPO`**：塞进源码目录会产生未跟踪文件，
`gate` 的 `clean_worktree` 判据会失败；且补丁 bench 的 `REPO = Path(__file__).parents[2]`
会算成 `/workspace/deepep` 之外的路径，靠 `GOLDEN_DIR` 显式补 golden 才能 `import common`。

**sha 一致性**：新仓 `bench_v2_bandwidth.py` 与 `/work/source/benchmarks/clos/bench_v2_bandwidth.py`
的 sha256 均为 `e705d662…`，性能阶段 `official_logical_GBps` 口径不受影响；
补丁的 `bench_v*_precision.py` 与 main 仓 API 的兼容性需在换库后重验。

   是历史快照，实际以本文件与 `run_round2.py` 的八机实现为准；指南正文未在本次改动范围内。
