## 3. 统一 Buffer 与仅精度

- 两个批次均使用**一次 `dist.init_process_group`**，同一批 torchrun worker 连续执行所有 case，不再每 case 重建通信环境。
- V1 使用一个 Buffer 覆盖全部 200 例；V2 因 `ElasticBuffer` 的 hidden/topk/dtype 为构造参数，按兼容配置分 26 组复用，tokens 在预留容量内变化（workspace 由与真实 `get_buffer_size_hint` 逐位校准的公式估算）。
- D组 8 组合：每 rank 3 次 Buffer 初始化（V1 一个 + V2 按 dtype 两组）。
- 所有 worker 携带 `--precision-only`：`precision.json.passed=true`、`result.json.operators={}`，无 profiler/计时/带宽/GBps/CV；本文件**不含任何性能数字**。
- 校验：两节点对同一 variant 的逐 rank 摘要 digest 完全一致（294 例 0 mismatch），32 rank 全部 `precision_only=true` 且 `exit.code=0`。

## 4. 数据文件与口径

[precision_20261126_ep32.csv](./precision_20261126_ep32.csv) 共 302 行：

| 字段 | 含义 |
|---|---|
| `batch` | `ep32_d_group` 或 `ep32_ab200` |
| `variant`, `api`, `group`, `source_id`, `dtype`, `expand` | 用例标识（`source_id` 对应设计文档 A/B/D 组编号） |
| `ep_size`, `nnodes`, `num_tokens`, `hidden`, `num_topk`, `experts_per_rank`, `aiv` | 精度用例参数 |
| `ranks_passed_node0/1`, `ranks_total` | 两节点各 16 rank 通过数，合计 32 |
| `precision_only`, `operators_empty` | 未采集性能的断言 |
| `buffer_initializations`, `teardown_scopes` | 复用证据与销毁范围 |
| `digest` | 该 variant 的逐 rank 校验摘要 SHA256 |
| `state`, `result_location` | 结果状态与原始产物位置 |

`digest` = SHA256 of `local_rank:precision.passed:result.precision_passed:(operators=={}):exit.code` 按 local rank 0–15 以 `|` 连接。A/B 批次两节点 digest 已验证一致；D组由本地文件重算、两节点一致。
