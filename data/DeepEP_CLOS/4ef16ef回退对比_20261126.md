## 1. 目的与做法

`基线对比分析_20261125.md` 第 333 行建议「复跑 EP32 的 2 个 −11% 离群点」。两个 dispatch 离群点都是 `hidden=2816 / aiv=32`，而 `4ef16ef`（"Use measured EP128 launch plans for BF16 H2816", 2026-11-15）恰好是该形状 launch plan 的引入点，因此重编译该版本、重跑这 2 例，判断劣化是否由该版本之后的源码改动引入。

**单一变量设计**：只把加载的 `deep_ep` 运行库换成重编译的 4ef16ef wheel（`/workspace/runtime_4ef16ef` + `PYTHONPATH` 覆盖）；基准脚本、全部参数、驱动、输出口径与 83252a5 基线完全一致。现有 83252a5 源码/运行库/conda site-packages **从未改动**，不设 `PYTHONPATH` 即可切回。

| 项 | 基线（83252a5） | 回退重跑（4ef16ef） |
|---|---|---|
| deepep 运行库 | `83252a54…` | `4ef16ef6…` |
| 基准脚本 `bench_v2_bandwidth.py` | `e705d662…` | 同（未改） |
| 驱动 / CANN / 编译器 | 25.8.rc10 / 9.2.1 / GNU 13.3.0 | 同（逐字段核对一致） |
| shmem revision | `a5e55f75…` | `29fad12…`（4ef16ef lock 锁定） |
| 参数 | EP32 / nnodes=2 / H2816 / aiv32 / topk8 / epr8 / warmup10 / iter30 / seed20260823 / uniform / bf16 / expand1 | 同 |
| 大页 | 关 | 关 |

- 目标 case：index 001（tokens=8192）、index 007（tokens=16384），均 EP32 双机 .6/.7，各 16 卡。
- 编译：在 .4 已有的 pwq 编译容器内**离线**重编译（本地 git 对象 + `29fad12` shmem + 已装 venv，无联网），`build.exit=0`、CPU pytest **256 passed**、两机 `.so` sha256 全等。证据见 [results_20261126_4ef16ef_runtime_manifest.json](./results_20261126_4ef16ef_runtime_manifest.json)、[results_20261126_4ef16ef_preflight.json](./results_20261126_4ef16ef_preflight.json)。
- 结果校验：2 例 × 2 节点全部 `suite_exit.code=0`、`report.passed=true`、4 op × 32 rank 覆盖完整、数值有限为正、`device_span_us≥device_sum_us`、`huge_pages` 未开、两机同 run_id。见 [results_20261126_4ef16ef_validation.json](./results_20261126_4ef16ef_validation.json)。

## 2. 结果（`official_logical_GBps` 逐 rank 算术均值，GB/s/rank）

偏差 = (回退重跑 − 基线) / 基线 × 100%。完整逐项见 [results_20261126_4ef16ef_ep32_replay_compare.csv](./results_20261126_4ef16ef_ep32_replay_compare.csv)。

| case | op | 基线 | 4ef16ef | 偏差 |
|---|---|---|---|---|
| 001 (T=8192) | dispatch | 241.014 | 228.902 | **−5.03%** |
| 001 | cached-dispatch | 319.756 | 258.825 | **−19.06%** |
| 001 | combine_unweighted | 327.127 | 250.511 | **−23.42%** |
| 001 | combine_weighted | 223.397 | 208.198 | **−6.80%** |
| 007 (T=16384) | dispatch | 250.550 | 235.571 | **−5.98%** |

| 007 | combine_unweighted | 327.110 | 259.336 | **−20.72%** |
| 007 | combine_weighted | 219.747 | 217.965 | **−0.81%** |

**观察（描述性，不是归因结论）**：

- 4ef16ef 回退版在 8 个对比项上**全部低于** 83252a5 基线，无一例外。
- 降幅最大的是 `cached-dispatch`（−19% ~ −20.5%）与 `combine_unweighted`（−20.7% ~ −23.4%）；`dispatch` 降 5–6%，`combine_weighted` 从 −0.8% 到 −6.8%。
- **回退到 4ef16ef 并未「修复」dispatch 的 −11% 离群点**：dispatch 反而比基线再低 5–6%。因此基线表里 dispatch 随 EP 增大而偏低的现象，不是「4ef16ef 之后的某个改动引入、回退即可恢复」的简单情形。
- 这与「4ef16ef 更旧」的直觉一致，但**不能据此判定 4ef16ef 本身是劣化原因**：见下一节的混淆变量。

## 3. 限制（判定前必须确认）

1. **不是同一个 shmem**：基线运行库 shmem `a5e55f75…`，4ef16ef 按 `dependencies.lock.json` 锁定 `29fad12…`（pwq 现成 SDK 又是 `c485ee7…`）。这是**不可消除的混淆变量**，且最可能影响 cached/combine 路径 —— 这两条恰是降幅最大的列。
2. **相隔 73 个提交**（41 个改过 `csrc/`），是「单点回退」而非完整版本回归；中间任何改动都可能造成差异。
3. **编译工具链一致（已逐字段核对）**：CANN 9.2.1（timestamp `20261024_000123916`）、GNU 13.3.0、cmake 3.28.3、python 3.13.16、pybind11 3.0.4、Ascend950 / Release —— 这一项**不是**混淆变量；剩余差异来自 deepep 源码 + 锁定的 shmem revision。
4. **仅 2 例**、EP32 单机拓扑（双机各 16 卡）、H2816、aiv32、bf16、expand1；无 EP8/16/64、无 fp8、无 expand=0、无其它 hidden/aiv。
5. **单次采样**（warmup=10 / iterations=30 的一次运行），无重复、无置信区间；`delta_pct` 是描述性差异，不能做统计显著性或严格归因。
6. `plan.json.identity.revision` 是基准脚本源码树版本（83252a5），**不代表加载的运行库**；运行库证据以 runtime_manifest.json 与 `.so` sha256 为准。
7. **测量成功 ≠ 无退化**：suite/report/rank 校验全通过只说明数据可采信；是否退化要看第 2 节数值，且需匹配计时边界（`comm_us` 是完整通信核，非隔离 NIC 计时）。
8. **未开 1G 大页**（`--huge-pages` 关闭），本结果不可与 [1G大页重测结果_20261126.md](./1G大页重测结果_20261126.md) 混用。
9. 当前 report 的 `official_logical_bytes` 在 dispatch/cached 含索引与权重、combine 为 BF16 x，与历史表「纯 BF16 payload」描述不完全一致；跨表对比前须对齐分子。

⇒ **结论边界**：本次结果只说明「在 4ef16ef 源码 + 29fad12 shmem 的组合下，这 2 个 case 比 83252a5 基线更慢」。要定位 dispatch 离群点的根因，需要控制 shmem revision 后做 A/B，并对 4ef16ef→83252a5 之间的改动做二分，而不是把本次 delta 读作「版本回退导致劣化」。
