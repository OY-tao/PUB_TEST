## 核实出的关键常量

| 常量 | 值 | 位置 | **性质** |
|---|---|---|---|
| `_MAX_TOPK` | **128** | `elastic_v2.py:45` | ✅ **真实校验**（在 415 / 1277 / 1368 三处 raise） |
| `_MAX_NUM_AIV` | **64**（架构 3510）<br>**48**（架构 2201） | `config_v2.py:23,25` | ✅ **真实校验**（`num_aiv > _MAX_NUM_AIV` 时 raise） |
| `_MAX_SHMEM_INTRANODE_RANKS` | 1024 | `elastic_v2.py:44`<br>`config_v2.py:29` | ⚠️ **节点内 rank 数**，不是专家数 |
| `_MAX_LOCAL_EXPERTS_FOR_SIZE_HINT` | 1024 | `config_v2.py:30` | ⚠️ **仅 size hint 估算**，不是校验 |
| `_MAX_TOPK_FOR_SIZE_HINT` | 128 | `config_v2.py:31` | ⚠️ **仅 size hint 估算**，不是校验 |

⚠️ **`_MAX_TOPK` 与 `_MAX_TOPK_FOR_SIZE_HINT` 同名不同义**：
前者是 dispatch 时的硬校验，后者只影响 workspace 预估值。
两者数值恰好都是 128，容易混淆。

## 核实出的真实校验（原文）

### V1 `buffer.py`

```python
# :110  构造时只查 > 0，无上界
if num_max_tokens_per_rank <= 0:
    raise ValueError("num_max_tokens_per_rank must be positive")

# :509  dispatch 时查 token 数不超容量
if x_tensor.size(0) > self.num_max_tokens_per_rank:
    raise ValueError("local token count exceeds num_max_tokens_per_rank")
```

**没有** hidden / topk / experts 的任何边界校验。

### V2 `elastic.py`

```python
# :45   真实 topk 上限
_MAX_TOPK = 128

# :230  hidden 只查 > 0，无上界
if num_max_tokens_per_rank <= 0 or hidden <= 0:
    raise ValueError("...must be positive when num_bytes is not provided")

# :415 / :1277 / :1368  topk 三处校验
if num_topk > _MAX_TOPK:
    raise ValueError(f"num_topk must not exceed {_MAX_TOPK}")

# :1380  hidden 只与构造值比对，无 %128
if x.size(1) != self.hidden:
    raise ValueError("x hidden size does not match ElasticBuffer.hidden")
```

## 结论

**Python 层几乎没有形状上界校验，真正的限制在 kernel/workspace 层。**
因此"边界测试"必须区分：参数层拒绝 / 算子拒绝 / kernel OOM 三种失败形态，
详见 [`../边界与异常用例清单_2to16P.md`](../边界与异常用例清单_2to16P.md) 第一章。
