## 二·五、边界来源已核实（2026-11-27 修正）

**问题**：初版边界表把**库文档**的推荐值当成了**算子校验**，
经回源码逐条核实，三者不一致。

### 三个来源不能混用

| 来源 | 性质 | 能作判据 |
|---|---|---|
| 库文档（`docs/*.md`） | 声明支持范围 | ❌ |
| bench 参数校验（`bench_v2_bandwidth.py:137-141`） | 基准脚本入参检查 | ✅ 但只管 bench |
| **算子源码校验** | 真正的 API 契约 | ✅ **真正的算子边界** |

### ⚠️ 2026-11-27 追加：拿到官方约束，我此前的结论是错的

用户提供了官方参数约束，这些数字**在开源 Python 代码里完全搜不到**（在 C++/kernel 层），
所以只查 Python 源码会得出"无上界"的错误结论。

| 参数 | **官方约束** | 我之前写的 | 差异 |
|---|---|---|---|
| **EP 数** | **2 ~ 1024** | 256（bench choices） | 官方允许更大 |
| **专家数 E** | `E % EP == 0` 且<br>`4×(au(EP,8)+au(E,8))+au(EP,32) ≤ 221120` | 无显式上界 | **完全不知道公式** |
| **H（BF16→BF16）** | **≤ 98304** | 7168 | **少了 13.7 倍** |
| **H（FP8→BF16）** | **≤ 109536** | 7168 | **少了 15.3 倍** |
| **S（tokens/rank）** | `< num_max_tokens_per_rank` | 16384 | 官方无固定值 |

**两条重要推论**：

1. **公式约束是宽松兜底**：即使 EP=E=1024，公式值仅 9216，占上限 221120 的 **4.2%**。
   求解饱和点得 E 可到 55264、EP 可到 43400 ⇒ **在 2~1024 内永不拒绝**，不该作为用例设计依据。

2. **H 是最大盲区**：官方 98304，泛化只测到 7168，
   **上限是已测最大值的 13.7 倍，中间完全空白**。
   这比我之前说的"topk 32~127 空白"严重得多。

### 核实结果（与初版差异）

| 项 | **源码真实校验** | 文档 | 初版写的 |
|---|---|---|---|
| hidden 上界 | **无**（只查 `>0`） | 7168 | ❌ 7168 |
| hidden 对齐 | V2 无 `%128`；bench 才要求 | BF16 16 / FP8 128 | ❌ 硬约束 |
| topk 上界 | **V2 `_MAX_TOPK = 128`** | 16 / 32 | ❌ 16 / 32 |
| tokens 上界 | **无**（只查 `>0` 与容量） | 16384 | ❌ 16384 |
| 专家数 E | **无显式上界** | ≤1024 | ❌ ≤1024 |
| `1024` 的真身 | `_MAX_SHMEM_INTRANODE_RANKS`（**rank 数**）<br>`_MAX_LOCAL_EXPERTS_FOR_SIZE_HINT`（**仅估算**） | — | ❌ 当专家上限 |
| `num_aiv` | **64（架构 3510）/ 48（架构 2201）** | — | 按 64 写 |

### 按官方约束重算的泛化覆盖率

| 维度 | 官方范围 | 泛化覆盖 | 覆盖率 |
|---|---|---|---|
| **EP** | 2 ~ **1024** | 2 ~ **16** | **1.6%** |
| **H** | ≤ **98304**（BF16） | ≤ **7168** | **7.3%** |
| **E** | ≤ 1024 | 2 ~ 1024 | **100%** ✅ |
| 公式 | ≤221120 | 全部满足 | 100% ✅ |

**E 维度完整，EP 和 H 都不到 10%。**
EP 的空白受硬件限制（32P 需 2 机、1024P 需 64 机），可接受；
**H 的空白是纯粹的设计遗漏，必须补**。

#### E5 根因已在源码层定位（我核实）

**两版都只校验 topk 的"宽度"，不校验"取值"**：

```python
# elastic_v2.py:607  —— 只查 num_topk 这个数，不查 topk_idx 里的每个元素
if num_topk > num_experts:
    raise ValueError("num_topk must not exceed num_experts")

# buffer_v1.py      —— 搜不到任何 topk_idx 取值范围校验
```

⇒ `topk_idx` 里出现 ≥ `num_experts` 的值时，Python 层**直接放行**，
kernel 收到越界 expert id 后 vector core exception。

**这是真实的输入校验缺口**，比清单原本想测的"容量校验"更有价值。

⚠️ **口径差异必须记住**：本轮用**越界 expert id**，非清单字面的**超容量 tokens**：

| 场景 | 测什么 | 状态 |
|---|---|---|
| 越界 expert id | 输入合法性校验缺失 | ✅ **已发现崩溃** |
| 超容量 tokens | 算子容量校验是否生效（应报 `local token count exceeds`） | ❌ **仍未验证** |

两者是不同维度，**不能互相替代**。
