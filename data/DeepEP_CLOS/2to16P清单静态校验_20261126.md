## 4. 判据冲突与执行层缺口（仅登记，不补代码、不跑）

清单本身写「仅清单」，但按 `bench_v2_precision.py:140-142` 与边界 md 逐条比对，发现以下不能直接按字面执行的点：

| # | 项 | 冲突 |
|---|---|---|
| 1 | S3 `hidden=16`（BF16 下界） | 清单称 BF16 16 倍数合法，但 bench 参数校验是 `hidden % 128` → **会被 `p.error` 误拒** |
| 2 | S7 `tokens=32768` | 超 V1 上限，但参数层**没有** `tokens>16384` 硬拒 → 不会按清单「预期被拒」被拦 |
| 3 | S8 `hidden=8192` | 超 V1 上限 7168，参数层不拒（且 `8192%128==0` 能过） |
| 4 | X5 `topk=32` | 清单写「V1 应拒绝」，但参数校验是 `num_topk > min(128, ep×epr)`，32 不会触发 |
| 5 | X7 `E=1025` | 无 `E<=1024` 显式参数校验，`epr=1025/ep` 非整数，拒绝点不明 |
| 6 | X6 `topk=P+1` | 边界 md 写 `min(128, ep×epr)`，清单约束表与生成器写 `min(32, ep×epr)`，**128/32 口径不一致**；且实际只在参数层 `p.error` 拦截，到不了 `rng.sample` 路由层 |
| 7 | 判据形式 | 边界 md 明确「退出码非 0 且 stderr 有明确提示，不能是 segfault 或挂死」，需要包装脚本采集 stderr，单次 bench 调用无法判定 |
| 8 | E1~E9 多轮 handle 编排 | 「两轮 dispatch 选择性 combine」「同 handle 两次 combine」「2→1 乱序 combine」「超容量非法输入后仍算对第1轮」「handle 错配逐 token 比对」等，**单次 `--precision-only` 调用无法表达**；md 第 137 行自列此问题。`scripts/lifecycle_test.py` 只覆盖构造/销毁 4 项，不含多轮编排 |
| 9 | 异常次数口径 | md 第 72 行写「18 次」，批次表第 109 行写「实际 16 次」；按 E1-6×2 + E7-9×1 = 15，三处不一致 |

⇒ 真正执行 2to16P 前需补：① S7/S8/X5/X7 的「预期被拒」判定层；② E1~E9 多轮驱动脚本；③ 128/32 口径统一。本次均**未实现、未执行**。
